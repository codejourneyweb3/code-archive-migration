## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

## Project rules (AutoSchool 360, migrated from the AutoTable desktop app)

- School rules (grading bands, report-card classification, promotion average, fee balances) live as pure functions in `src/lib/academics.ts` and `src/lib/finance.ts`; pages compute from loaded rows and never re-implement them — keeps every screen consistent with the desktop app's results.
- Data is read client-side with `fetchAll` + TanStack Query keys `["table", name]` (`src/lib/db.ts`); mutations call `useInvalidate(...tables)` — one cache shape for every table.
- Signed-in pages live under the pathless `src/routes/_app.tsx` layout with `ssr: false`, because the session is stored in the browser.
- Access: roles in `user_roles` (`admin`, `data_entrant`), page grants in `profiles.allowed_pages` using the desktop route tags in `src/lib/pages.ts`; never rename tags — imported desktop accounts carry them.
- First-visit access is granted only by security-definer RPCs (`claim_legacy_account` via verified email, `redeem_invite`, `claim_first_admin`); never assign roles from client code.
- Table ids are `bigint generated by default as identity` so imported desktop records keep their original ids.
- Student photos and the school logo are stored as paths in the private `school-media` bucket and shown through signed URLs.
- Printing (report cards, slips) renders A4 sheets into a `.print-root` element and calls `window.print()`; the browser dialog provides printer choice and Save as PDF.
